======================================================================
FEATURE L2.8 - DATASET SOURCE NOTES (CSE-CIC-IDS2018)
======================================================================

OFFICIAL DATASET
-----------------
Name: CSE-CIC-IDS2018 (Communications Security Establishment & Canadian
Institute for Cybersecurity Intrusion Detection Dataset 2018)
Official page: https://www.unb.ca/cic/datasets/ids-2018.html
Citation: Sharafaldin, I., Lashkari, A.H., Ghorbani, A.A. "Toward
Generating a New Intrusion Detection Dataset and Intrusion Traffic
Characterization." ICISSP, January 2018.

Feature extraction tool: CICFlowMeter-V3 (stated explicitly on the
official page: "80 features extracted from the captured traffic using
CICFlowMeter-V3"). This matches this project's raw training CSV's exact
column count (80).

HOSTING
-------
The full dataset (both raw captures and processed CSVs) is hosted in a
single public AWS S3 bucket: s3://cse-cic-ids2018/
Accessible anonymously via `aws s3 ... --no-sign-request` (official
instruction quoted on the CIC page) and via plain HTTPS
(https://cse-cic-ids2018.s3.amazonaws.com/...) - both independently
verified working in this session.

Bucket has exactly two top-level prefixes:
  "Original Network Traffic and Log data/"   <- raw PCAP + Windows .evtx logs, per day, per host
  "Processed Traffic Data for ML Algorithms/" <- the 10 per-day CSVs this project uses

This project had ALREADY downloaded 3 of the 10 processed CSVs from this
exact bucket in a prior session (see results/external_dataset_preparation/
download_manifest.json) for Feature 16's frozen-generalization evaluation
- that prior evidence is what first pointed this task at the correct
bucket location; this task independently re-verified it live.

RAW PCAP AVAILABILITY
----------------------
Every one of the 10 days has a corresponding "Original Network Traffic and
Log data/<Day>/" folder containing exactly two files: "pcap.zip" (the raw
captures) and "logs.zip" (Windows Event Logs, NOT packet data). Sizes for
the 4 days already relevant to this project (Thursday-01-03-2018, the
current training day, plus the 3 already-downloaded external-evaluation
days):

  Thursday-01-03-2018:   pcap.zip ~52.36 GB   logs.zip ~227.6 MB
  Wednesday-28-02-2018:  pcap.zip ~53.25 GB   logs.zip ~226.6 MB
  Wednesday-14-02-2018:  pcap.zip ~39.91 GB   logs.zip ~140.2 MB
  Wednesday-21-02-2018:  pcap.zip ~53.46 GB   logs.zip ~194.6 MB

Every pcap.zip is a ZIP archive of ~440+ individual per-host capture
files (named by internal AWS testbed hostname/IP, e.g.
"capDESKTOP-AN3U28N-172.31.64.111" or "UCAP172.31.69.15"), NOT a single
unified whole-day capture. This means the CSE-CIC-IDS2018 processed CSVs
were almost certainly generated by running CICFlowMeter-V3 across
multiple per-host captures and merging the resulting flows - a materially
more complex generation pipeline than "one pcap in, one CSV out."

WHY NOTHING WAS BULK-DOWNLOADED
---------------------------------
Every pcap.zip is 40-53 GB - clearly "enormous" by this task's own
threshold. Per Step 4's explicit instruction, this was documented and NOT
downloaded in bulk. Instead:
  - The ZIP's central directory (file listing, sizes, no packet content)
    was read via targeted HTTP Range requests: ~56.5 KB of network
    transfer to enumerate all 444 entries of the Thursday-01-03-2018
    archive - a ~1,000,000x reduction versus downloading the full 52 GB.
  - ONE single small entry (the smallest of the 444, 406,269 bytes
    uncompressed) was extracted the same way (targeted Range requests,
    ~91.7 KB total network transfer) and verified to be a genuine,
    correctly-dated libpcap file - see provenance.json for full detail.

ORIGINAL CICFLOWMETER VERSION
-------------------------------
The official CIC dataset page states "CICFlowMeter-V3" was used. The
current public repository (github.com/ahlashkari/CICFlowMeter) is at
V4.0 and has ZERO git tags and ZERO GitHub releases - there is no cleanly
identifiable V3 commit/tag in the currently available public repository
history. The exact source snapshot used in 2018 is therefore NOT
reproducible from currently available public evidence alone. This
repository was NOT cloned, built, or installed (no Maven/Java
dependencies were touched), per this task's explicit instruction.

WHAT THIS DOES AND DOES NOT ESTABLISH
----------------------------------------
DOES establish: a genuine, officially-sourced, correctly-dated raw PCAP
capture exists and is technically obtainable (in small, targeted pieces)
for Thursday-01-03-2018 - the exact day this project's training CSV
covers. This is qualitatively different from, and more trustworthy than,
Feature L2.7's third-party cicflowmeter 0.5.0 reimplementation, since it
is data from the ACTUAL dataset generation process, not a different
codebase's reconstruction.

Does NOT establish: that any specific flow in the training CSV can be
traced back to specific packets in this PCAP (would require processing
much more of the 52 GB archive, and ideally the actual CICFlowMeter-V3
binary, neither of which was attempted here), nor that the raw capture's
broader UTC time window exactly reconciles with the processed CSV's
narrower stated window (unresolved - a timezone/window-boundary question,
not a provenance red flag by itself).
