======================================================================
K-STEP FORECASTING REPORT (FEATURE 12)
======================================================================

1. OBJECTIVE
   Recursive K-step forecasting of future network-state vectors using the frozen Feature 10 LSTM World Model.

2. MATHEMATICAL FORMULATION
   S(t+2) = F_theta(S(t-8),...,S(t),Shat(t+1)); S(t+3) = F_theta(S(t-7),...,S(t),Shat(t+1),Shat(t+2)); etc.

3. RECURSIVE ROLLOUT METHOD
   Feature 12 performs recursive K-step forecasting using the frozen LSTM World Model. After the first prediction, each subsequent forecast uses the model's own previous prediction rather than the ground-truth future state.

4. WHY RECURSIVE FORECASTING IS USED
   Research question: how far into the future can the learned network-state dynamics
   model forecast before prediction error becomes substantial? Recursive (free-running)
   rollout is the only way to measure this honestly, since teacher forcing (feeding the
   true future state at every step) would not measure the model's own error compounding.

16. TEST LIMITATION
   The current TEST partition contains 2871 sequences: 2871 Benign, 0 Infiltration. Feature 12 can evaluate future-state REGRESSION on the TEST partition (MSE/RMSE/MAE at each horizon), but it cannot establish attack-class detection or attack-progression performance on TEST, because there are no positive examples to detect. Attack progression evaluation will come later.

17. KNOWN LIMITATIONS
   - Ground-truth future states beyond h=1 are derived via pipeline.transform(), not
     stored natively by Feature 7; verified consistent with Feature 7's own h=1 arrays.
   - Recursive rollout compounds LSTM regression-to-mean behavior (documented in Feature
     10/11) across steps; see error accumulation results for whether this worsens error.
   - Single continuous-day capture: generalization to other days/networks is untested.

18. WHAT FEATURE 12 DOES NOT IMPLEMENT
   Feature 12 predicts future network-state vectors. It does not yet calculate attacker-progression probability.
   Also not implemented: MITRE ATT&CK mapping, SHAP/attention explanations, risk scoring,
   mitigation, dashboard changes, or multi-day dataset expansion.

19. RECOMMENDED FEATURE 13
   Use the K-step forecast trajectory (and/or Feature 11's frozen classifier applied to
   each forecasted state) to define an attack-progression probability over the forecast
   horizon, still respecting the chronological split and TEST-set label limitation.
