F. DATA-QUALITY FINDINGS  [VERIFIED / OBSERVED]
----------------------------------------------------------------------

1. EMBEDDED HEADER ROWS vary by file: Wednesday-28-02-2018 has 33
   (same CICFlowMeter artifact as the 25 found in the current dev
   dataset); Wednesday-14-02-2018 and Wednesday-21-02-2018 have 0
   (independently confirmed via grep).

2. *** CRITICAL *** Wednesday-14-02-2018 AND Wednesday-21-02-2018 both
   contain EXACTLY 1,048,575 rows = 2^20 - 1 = Excel's maximum
   worksheet row limit (1,048,576) minus one header row. This is very
   unlikely to be coincidental and strongly suggests both files were
   TRUNCATED during CIC's dataset preparation (e.g. an Excel open/
   re-save step), and may NOT contain the complete day's capture. This
   is confirmed NOT to be a download artifact: each file's byte size on
   S3 is fully self-consistent with exactly this many rows.
   Corroborating evidence: Wednesday-21-02-2018 stops at 10:43:21, over
   two hours before the ~12:59:59 end-time pattern seen in the other
   two files - consistent with a mid-capture cutoff. Wednesday-14-02-2018
   does reach 12:59:59, so it is less clearly affected by this
   particular signal, but the row-count coincidence is unexplained.
   RECOMMENDATION: treat both as POSSIBLY INCOMPLETE, especially
   Wednesday-21-02-2018, when designing any evaluation that depends on
   complete-day coverage.

3. Wednesday-14-02-2018 has 5 rows (0.0005%) with implausible pre-2018
   timestamps (e.g. "05/01/1970 03:01:17"), all with Dst Port=0,
   Protocol=0, Label=Benign. A genuine pre-existing source-data issue,
   negligible in scale, not modified here.

4. Exact duplicate rows: Wednesday-28-02-2018 has 6,089 (~1.0%),
   Wednesday-21-02-2018 has 17,557 (~1.7%), Wednesday-14-02-2018 has an
   unusually high 225,628 (~21.5%, independently verified with
   pandas.duplicated()). Investigated: Wednesday-14-02's duplicates are
   concentrated almost entirely in FTP-BruteForce/SSH-Bruteforce rows,
   consistent with automated brute-force tooling generating many
   byte-identical flow records - likely a genuine attack-traffic
   characteristic, not necessarily a pipeline defect. This needs a
   deliberate decision in a future cleaning step, not blind removal.

5. Flow Byts/s / Flow Pkts/s Infinity values: present in
   Wednesday-28-02-2018 (2,128 / 6,169) and Wednesday-14-02-2018
   (1,547 / 3,824), matching the known CICFlowMeter zero-duration-flow
   division-by-zero pattern documented in Feature 2. ZERO Infinity
   values in Wednesday-21-02-2018 (DDoS traffic rarely has zero-duration
   flows). No literal "NaN" strings found in any of the 3 files.

None of these issues were cleaned, removed, or modified - inspection
only, as required.
