   Deterministic, rule-based mapping of observed/predicted network evidence and Feature 13 context onto candidate MITRE ATT&CK stages.

7. EVIDENCE SCORING METHOD
   Sum of triggered rules' score_contribution per stage, capped at 100 (or the stage's explicit
   cap for candidate-only stages). This is a 'Stage Evidence Score', NOT a probability, NOT
   model confidence, NOT an ATT&CK probability, and NOT prediction accuracy.

8. PRIMARY-STAGE SELECTION LOGIC
   Highest evidence_score across all 7 stages; if that maximum is below 30,
   primary_stage = UNKNOWN / INSUFFICIENT_EVIDENCE. All 7 stage scores are always preserved, never deleted.

9. UNKNOWN LOGIC
   See item 8. Verified via self-test (all-None evidence -> UNKNOWN).

10. FEATURE 13 INTEGRATION
   P(Infiltration) is attached to each PREDICTED evidence point as a separate contextual field
   (feature13_attack_probability). It is NEVER fused into or converted into a stage evidence score.

11. OBSERVED VS PREDICTED EVIDENCE
   OBSERVED: raw values looked up directly from temporal_windows.csv at the sequence's current/last
   real window (input_end_window) - real data, not model output.
   PREDICTED: Feature 12's frozen-LSTM recursive rollout at K=1,2,3,5, inverse-transformed from
   scaled back to raw units via the Feature 7 train-fitted scaler (inverse_transform only, never fit).
   Ground-truth future states/labels are used ONLY for the separate evaluation/reproducibility
   checks below, never as mapper inputs.

12. EVALUATION METHODOLOGY (no ATT&CK ground truth available)
   The current dataset (Benign/Infilteration binary labels) contains NO legitimate ATT&CK stage ground truth. mitre_stage_confusion_matrix.json was intentionally NOT created, per the Feature 14 specification: 'Only create mitre_stage_confusion_matrix.json IF a legitimate ground-truth ATT&CK stage label actually exists.' ATT&CK classification accuracy/precision/recall/F1 CANNOT be claimed or computed.

17. LIMITATIONS
   - Lateral Movement evidence is structurally unavailable: this dataset has no source/destination
     IP addresses, so internal-destination-count evidence can never be computed here.
   - PREDICTED evidence lacks dst_port_nunique, observation_count, and avg_bytes_per_flow, because
     these are not part of the 68 features the LSTM predicts (they are Feature 6 window metadata,
     not state-vector features) - so Discovery/Reconnaissance rules that depend on them can only
     fire on OBSERVED evidence, never on PREDICTED evidence. See evidence_feature_availability
     in the metrics JSON for exact per-field availability percentages.
   - Reconnaissance and Initial Access are explicitly capped (candidate-only) because flow
     telemetry cannot establish attacker intent or confirm compromise.
   - This is network-evidence-based, transparent, rule-based reasoning; it is NOT a trained
     model and carries no learned generalization guarantees.

18. EXPLICIT STATEMENT

ATT&CK classification accuracy/precision/recall/F1 CANNOT be claimed or computed.
