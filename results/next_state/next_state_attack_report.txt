NEXT-STATE ATTACK PREDICTION REPORT (FEATURE 11)
======================================================================

1. OBJECTIVE
   Map the LSTM-predicted next network state S(t+1) to a discrete attack-state prediction (Benign/Infilteration).
   Feature 11 maps the LSTM-predicted next network state to a discrete attack-state prediction. It does not yet implement multi-step forecasting or attacker-progression probability.

2. ARCHITECTURE
   Frozen Feature 10 LSTM World Model (unmodified) + a separate downstream
   LogisticRegression state-to-attack classifier: {'max_iter': 2000, 'class_weight': 'balanced', 'random_state': 42, 'solver': 'lbfgs'}

3. RELATIONSHIP TO FEATURE 10
   The LSTM World Model (Feature 10, frozen and not retrained here) predicts the continuous 68-dimensional next network state from 10 historical states. Feature 11 adds a separate, downstream classifier that interprets ANY 68-dimensional state (ground-truth or LSTM-predicted) as an attack-state label. The LSTM remains purely a temporal-dynamics model; it was never given the attack label and was not modified in this feature.

4. ORACLE CLASSIFICATION METHODOLOGY (MODE A)
   Classifier trained on TRAIN ground-truth next states, evaluated on ground-truth next states for train/validation/test. Isolates state-representation separability from LSTM prediction error.

5. FULL PIPELINE METHODOLOGY (MODE B)
   Same frozen classifier, evaluated on LSTM-predicted next states (X_sequences_scaled -> frozen LSTM -> predicted state -> classifier) for train/validation/test. This is the actual CyberChess forecasting path.

   validation: n=3492, labels={'Benign': 1815, 'Infilteration': 1677}

17. TEST-SET LIMITATION
   The chronological TEST partition contains no positive Infiltration examples. Therefore, attack-class recall and ROC-AUC are not estimable on the current TEST partition. Test results should not be interpreted as a complete attack-detection evaluation.

18. KNOWN LIMITATIONS
   - TEST partition contains no Infiltration target windows; test metrics here
     characterize false-positive behavior on benign traffic only, in both modes.
   - The oracle-vs-pipeline difference on VALIDATION is descriptive, not a proof of
     causality (see comparison_statement).
   - Raw (uncalibrated) probabilities are reported; see item 14.
   - Single continuous-day capture: generalization to other days/networks is untested.
   Feature 8's Logistic Regression was trained on a FLATTENED 10x68=680-dimensional historical sequence (t-9..t) to predict the NEXT window's label directly. Feature 11's Logistic Regression is a different model: it maps ONE 68-dimensional FUTURE state vector (ground-truth or LSTM-predicted S(t+1)) to its attack-state label. They are not interchangeable and are not directly comparable as classifiers of the same input.

19. WHAT FEATURE 11 DOES NOT IMPLEMENT
   - K-step / multi-step forecasting
   - Attack-progression probability across multiple future windows
   - MITRE ATT&CK stage prediction
   - Explainability (SHAP or otherwise)
   - Autonomous mitigation
