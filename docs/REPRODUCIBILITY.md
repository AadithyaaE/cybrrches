# CyberChess — Reproducibility Guide

This document states plainly what can and cannot be reproduced from this
repository as checked into Git, and exactly what you need to add yourself.

**Honesty note:** full end-to-end reproduction of the original Features
1–16 research pipeline is **not possible from this repository alone**,
because several of the largest source/processed dataset files were
intentionally removed from Git (they exceed GitHub's 100 MB per-file
limit). Everything needed to *re-download and regenerate* them is
documented below, but this repository by itself only guarantees
reproducibility of the **frontend demo** and of any pipeline stage whose
required input artifacts remain checked in.

---

## 1. Python version

Two separate Python interpreters were used during this project's
development, with slightly different installed package versions (both
verified working, see `requirements.txt`'s header comment for the exact
breakdown):

- **Python 3.14.3** — used for the majority of the pipeline (Feature L1,
  most of Feature L2.x's data-preparation logic, Feature 17, Feature 18).
- **Python 3.12.10** — used specifically for PCAP-related features
  (requires `scapy`, which was not installed under 3.14.3 in this
  project's environment).

Either interpreter is expected to work for the core ML pipeline; only
PCAP-specific code (`src/data/pcap/`, `src/data/sandbox_capture/`)
requires `scapy`, which needs the interpreter it was actually installed
under (see `requirements.txt`).

The exact Python version used for the **original** Features 1–16 (before
the earliest visible project history) could not be established — no
environment snapshot from that period exists in the repository.

## 2. Dependency installation

```bash
pip install -r requirements.txt
```

`requirements.txt` was derived by inspecting actual `import` statements
across `src/` and `tests/`, not copied from a template. `scapy` is
optional and only needed for PCAP-related features.

**Official source (verified reachable, publicly documented, no signup required):**
- Dataset page: `https://www.unb.ca/cic/datasets/ids-2018.html`
- Public AWS S3 bucket (anonymous read, no AWS account needed):
  ```bash
  aws s3 cp --no-sign-request \
    "s3://cse-cic-ids2018/Processed Traffic Data for ML Algorithms/Thursday-01-03-2018_TrafficForML_CICFlowMeter.csv" \
    data/raw/Thursday-01-03-2018_TrafficForML_CICFlowMeter.csv
  ```
  (substitute the other day-filenames as needed; the bucket layout and every filename above were directly verified in this project's own `results/pcap_ground_truth_discovery/` and `results/external_dataset_preparation/download_manifest.json`.)
- Citation: Sharafaldin, Lashkari, Ghorbani — *"Toward Generating a New Intrusion Detection Dataset and Intrusion Traffic Characterization"*, ICISSP 2018.

After downloading the raw CSVs, the derived `data/processed/*` files can
be regenerated by running the Feature 1–6 pipeline scripts in order (see
Section 4).

## 4. Feature 1–18 pipeline order

```
Feature 1-6  (src/data/):
  inspect_dataset.py -> clean_dataset.py -> feature_audit.py ->
  prepare_features.py -> build_states.py -> build_temporal_windows.py

Feature 7    (src/data/split_temporal_data.py)
  Fits the ColumnTransformer preprocessing pipeline on TRAIN only.

Feature 8-11 (src/models/):
  train_logistic_baseline.py, train_random_forest_baseline.py,
  train_lstm_world_model.py, train_next_state_attack_classifier.py

Feature 12-15 (src/models/):
  k_step_forecaster.py + evaluate_k_step_forecasting.py,
  attack_progression_probability.py + evaluate_attack_progression_probability.py,
  mitre_stage_mapper.py + evaluate_mitre_stage_mapping.py,
  model_explainer.py + llm_explainer.py + evaluate_explainability.py

Feature 16   (src/data/prepare_external_dataset.py,
              src/models/evaluate_frozen_generalization.py)
  Frozen (never refit) evaluation on 3 external days.

Feature L1-L3.2 (src/data/pcap/, src/data/sandbox_contract/,
                  src/data/sandbox_capture/)
  Offline PCAP adapter, its audit/correction/reference-comparison history,
  and the (currently blocked) Sandbox lab capture contract - see
  results/pcap_validation/ and results/sandbox_capture/ for exactly what
  is and is not validated.

Feature 17   (src/experiments/cross_day_generalization/)
  Frozen-baseline reproduction + genuine multi-day training experiment
  (2 of 4 possible leave-one-day-out folds).

Feature 18   (src/experiments/demo/, frontend/src/pages/DemoPage.tsx)
  End-to-end demo wiring - no new computation, only reuses existing
  artifacts and existing frontend engines.
```

## 5. Frozen model / generalization evaluation

The frozen Feature 8–15 models are evaluated, **never retrained**, on 3
unseen external CSE-CIC-IDS2018 days (Feature 16) and on a genuine
multi-day training experiment (Feature 17). Re-running these requires the
external-day raw CSVs from Section 3. The trained model artifacts
themselves (`results/baseline/*.joblib`, `results/lstm/lstm_world_model.pt`,
`results/next_state/*.joblib`) **are** checked into this repository (each
well under the size limit) so the frozen evaluation can be re-run without
retraining, provided the external-day CSVs are downloaded first.

## 6. Frontend installation / build

```bash
cd frontend
npm install
npm run build      # output: frontend/dist/
npm run lint        # oxlint, 0 errors expected
npm run preview     # serves the production build locally
```

No environment variables are required. No local absolute paths are
referenced anywhere in the frontend source (verified by inspection).

## 7. What is required for the static demo

**Nothing outside this repository.** The frontend demo (`/demo` route,
Feature 18) and every other analysis page operate entirely from
pre-generated, real research-artifact JSON/CSV snapshots already checked
into `frontend/public/data/` and bundled as TypeScript constants under
`frontend/src/data/`. `npm install && npm run build` is sufficient — no
dataset download, no Python environment, no model retraining.

## 8. What is NOT included because of GitHub size constraints

The 10 files listed in Section 3, plus (not yet removed, but flagged as
future candidates for the same treatment):

- `results/baseline/random_forest_model.joblib` (75 MB) and the Feature 17
  fold-specific RandomForest models (96–201 MB each, currently untracked)
  — not required by the frontend, only by re-running the Python baseline
  training/evaluation scripts.
- Several `X_sequences*.npy` arrays under `data/processed/splits/` and
  `data/processed/frozen_generalization/` (58–82 MB each) — same
  reasoning.

None of these are required to build or run the frontend demo (Section 7).
They are only required to re-run specific Python evaluation/training
scripts from scratch.
